# Задание 6: Аудит активности пользователей и обнаружение инцидентов

## Описание

Набор утилит для включения аудита активности пользователей в Kubernetes, симуляции инцидентов и анализа `audit.log`. Автоматические шаги рассчитаны на кластер K3s; для других вариантов приведены подсказки в комментариях.

## Что реализовано

- **audit-policy.yaml** - политика аудита Kubernetes с уровнями RequestResponse для критичных ресурсов (pods, secrets, RBAC) и Metadata для остальных
  - **scripts/setup-audit.sh** - настройка аудита для K3s (копирует политику и перезапускает `k3s`)
  - **scripts/copy-audit-log.sh** - копирование `/var/log/kubernetes/audit.log` в корень задания
  - **scripts/simulate-incident.sh** - симуляция ключевых шагов атаки (доступ к secrets, `privileged` pod, `kubectl exec`, эскалация RBAC)
  - **scripts/analyze-audit.py** - упрощённый анализатор, формирующий `audit-extract.json`
- **analysis.md** - детальный отчет по выявленным инцидентам с рекомендациями по устранению
- **audit-extract.json** - структурированная выжимка подозрительных событий для интеграции с SIEM

## Использование

Все команды доступны через Makefile:

```bash
make setup      # Настроить Kubernetes с аудитом (автоопределение типа кластера)
make simulate   # Запустить симуляцию инцидентов
make analyze    # Скопировать логи и провести анализ
make status     # Показать состояние ресурсов
make validate   # Проверить наличие всех требуемых файлов
make clean      # Удалить созданные ресурсы
make help       # Показать все доступные команды
```

Автоматизированные команды рассчитаны на кластер K3s (потребуется запуск с `sudo` для настройки и копирования логов). Для других дистрибутивов воспользуйтесь инструкциями из описания задания.

## Детектируемые инциденты

1. **Доступ к secrets** - попытки чтения secrets от имени непривилегированных пользователей
2. **Привилегированные поды** - создание подов с `privileged: true`
3. **kubectl exec** - выполнение команд в подах системных namespace
4. **Эскалация прав** - создание RoleBinding с cluster-admin
5. **Удаление audit policy** - попытки отключения аудита

## Требования

- Kubernetes кластер (K3s, Minikube, Kind, или стандартный)
- Python 3.9+
- kubectl
- jq (для валидации JSON)
- sudo (для K3s и kubeadm кластеров)
